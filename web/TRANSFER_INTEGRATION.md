# Transfer integration

The dashboard has Home, Secrets, 2FA and Transfers routes. Normal development previews use the fixtures in `scripts/dashboard-mocks.ts`; production builds read chain data. The Home cards, OTP accounts, receipt tables, and chart all use the same fixture source.

Transfers are wired to the rail. The browser cannot call it directly, because it sends no CORS headers and answers the preflight with a 404, so `src/app/api/rail/[[...path]]/route.ts` relays the already signed body to `REWALL_RAIL_URL`. That proxy signs nothing, decrypts nothing, caches nothing, reads no body field and refuses any path outside the five Chainlink documents. `src/lib/rail.ts` is the only place a `Transfers` is constructed, so the SDK can never fall back to Chainlink's dormant deployment.

- Transfers subpages contain only tables, stacked vertically, above a balance card. The volume chart belongs to Home.
- `src/components/dashboard/rail.tsx` holds the balance for the connected wallet. Every rail call signs an EIP-712 message, so a poll would be a prompt per tick. The signed `/balances` body is recorded and replayed for 240 seconds, under the rail's 300 second window, which makes refreshing free. Nothing is read on mount.
- `src/components/dashboard/transfer-forms.tsx` holds the send, fund, withdraw and receipt panels. A send resolves `rewall.shielded` before it arms the button, pays with `hide-sender`, then writes the receipt with its grantees sealed in at creation. A payment whose receipt write fails is kept in `rewall.unwritten.<address>` and offered again, since the transaction id is the only handle on money that already moved.
- `src/components/dashboard/transfers.tsx` reads receipt secrets in the open vault under Sent. Shared comes from the watched-vault scan, decrypted only when a row is clicked.
- `src/components/dashboard/terminal-overview.tsx` has sent/shared counts. Monetary totals are unknown, never treated as zero.
- ENS has no reverse index, so a receipt granted to you is found by scanning the vaults you name. The watch list lives in `localStorage` keyed by the viewer's address, never in a record, because a public list of who you transact with is a social graph. Bounded at 5 names and 32 receipts each.
- `src/components/dashboard/volume-chart.tsx` accepts a presentation-only `TransferVolume` prop: `asset`, exact formatted `sentTotal` / `sharedTotal`, and daily `points` containing `label`, `sent`, `shared`. This is a chart view model, not a serialized receipt format. Supply 30 daily buckets for the selected asset. Keep exact amounts as integers/decimal strings upstream; convert only plotted values to numbers. Never combine assets or substitute USD without an actual price source.
- `src/components/dashboard/private-data.tsx` retains decrypted OTP accounts and receipts in memory, and runs the watched-vault scan. Wallet or vault changes remount it and wipe seed buffers. It signs only after an explicit user action.

`pnpm run check:rail` proves the proxy carries a real signature to the rail, relays the rail's own refusal with its wording and `request_id` intact, and refuses anything outside the five as JSON. `pnpm run check:transfers` proves the page loads with zero wallet prompts, that one signature buys the balance and every refresh after it is free, and that a name publishing no shielded address is refused before a prompt is spent. Both need `pnpm run serve` in `rail/` and the two `NEXT_PUBLIC_REWALL_*` addresses in `.env.local`.

`node scripts/check-mock-dashboard.mjs` checks the normal development preview, including sticky positioning, mock totals, Lexend labels, and the 32px welcome corner. `node scripts/check-dashboard.mjs` checks the live vault and all four routes against a production server. `node scripts/check-otp.mjs` runs an isolated browser fixture using the public RFC 6238 seed and chart test values; development OTP rows also use this public test material. The checks save screenshots and results under the ignored `artifacts/dashboard/` directory. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if Chromium is installed outside Playwright's default location.
